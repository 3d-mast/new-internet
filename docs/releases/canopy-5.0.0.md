# Canopy 5.0.0 Preview

**Canopy** — следующая природная версия `new-internet`. Полог леса устойчив потому, что множество ветвей перекрывают друг друга; Canopy 5 применяет тот же принцип к выбору маршрута: не дёргает рабочий путь из-за одного шумного измерения, но переключается немедленно, когда текущий выход действительно недоступен.

## Что изменено

### Zero-touch и отказоустойчивость

- новый кандидат на выход должен подтвердиться двумя последовательными циклами, если текущий маршрут остаётся рабочим;
- при падении текущего выхода резервный маршрут применяется сразу, без искусственной задержки;
- выбранный `SelectedExit` сохраняется до запуска локальных SOCKS/HTTP listeners, поэтому новый запрос больше не попадает в короткое окно со старым/пустым маршрутом;
- ошибки локальной настройки получают ограниченный exponential backoff: 1, 2, 4, 8, 16 секунд вместо повторов каждые 3 секунды;
- состояние перехода сбрасывается при отключении автопилота или исчезновении всех выходов.

### Безопасность wire framing

Wire-протокол остаётся **`LICHEN/2`**. Формат handshake не менялся, поэтому Canopy совместим с Reef 4, Rhizome 3 и Lichen.

- максимальный размер управляющего JSON-frame уменьшен с 1 MiB до 64 KiB;
- oversized frame отклоняется до выделения буфера под payload;
- один frame обязан содержать ровно одно JSON-значение: приписанный второй JSON/payload отклоняется;
- неизвестные JSON-поля по-прежнему принимаются, чтобы не ломать forward/backward compatibility.

### Windows и сервер

- новый `canopy.exe` и диагностический `canopy-console.exe`;
- повторный запуск открывает уже работающий локальный интерфейс;
- журнал: `canopy.log`;
- новый профиль использует `%APPDATA%\Canopy`, но автоматически подхватывает существующие `Reef`, `Rhizome`, `Lichen` и `MyceliumOne`, сохраняя Ed25519-идентичность;
- Docker/server binary переименован в `canopy`, режим `--server` сохранён.

## Проверки перед prerelease

CI обязан пройти:

- `go test ./...`;
- `go test -race ./...` на Linux;
- `go vet ./...`;
- тесты framing, route confirmation и retry backoff;
- `node --check internal/app/web/canopy.js`;
- Linux build + реальный smoke-test `/api/status` и встроенного GUI;
- Windows GUI build + console build + реальный smoke-test локального API и HTML;
- Docker build;
- создание Windows/Linux архивов и `SHA256SUMS.txt` только после успешных Linux/Windows jobs.

## Совместимость

- wire protocol: `LICHEN/2`;
- invitation prefix: `lch1.`;
- config schema: без повышения версии;
- существующая Ed25519 identity и доверие мигрируют без генерации нового узла.

## Ограничения

Canopy 5 **не реализует** Wintun/TUN, UDP dataplane, QUIC hole punching, произвольную IP-маршрутизацию или гарантированный обход любого NAT/firewall. Системный режим Windows по-прежнему использует HTTP proxy. Логические IPv4/IPv6 — идентификаторы overlay, а не адрес реально созданного сетевого интерфейса Windows.
