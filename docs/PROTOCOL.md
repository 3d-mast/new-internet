# MYCELIUM/1 — черновик протокола

## 1. Цели

MYCELIUM/1 создаёт оверлейную сеть поверх уже существующих IP-сетей. Узлы не получают доверие из факта подключения: каждое действие проверяется отдельной возможностью.

## 2. Идентичность

- Ключ: Ed25519.
- `NodeID = base32(lowercase, SHA-256(public_key)[0:16])`.
- Самоподписанный TLS-сертификат содержит тот же Ed25519-ключ.
- При рукопожатии сертификат, `NodeID`, публичный ключ и подпись должны совпасть.

IP-адрес является только текущим маршрутом до узла и не участвует в доверии.

## 3. Транспорт

MVP использует TCP + TLS 1.3. После TLS клиент передаёт JSON-кадр с 32-битной длиной:

```json
{
  "version": "MYCELIUM/1",
  "node_id": "...",
  "name": "workstation",
  "public_key": "...",
  "purpose": "join|control|exit|tunnel",
  "target": "example.org:443",
  "timestamp": 1785830000,
  "signature": "..."
}
```

После положительного ответа для `exit` и `tunnel` поток становится прозрачным байтовым каналом.

## 4. Приглашения

Приглашение `myc1.<base64url(JSON)>` включает:

- идентичность создателя;
- доступные адреса;
- одноразовый секрет;
- срок действия;
- точный набор выдаваемых разрешений;
- подпись создателя.

Секрет хранится у создателя до использования. После успешного подключения он помечается использованным.

## 5. Разрешения

| Возможность | Значение |
|---|---|
| `use_exit` | узел может направлять публичный TCP-трафик в интернет |
| `access_lan` | узел может обращаться к приватным/локальным TCP-адресам |
| `relay` | резерв под транзит чужих зашифрованных потоков |

Разрешения направленные: то, что A разрешил B, не означает, что B разрешил это A.

## 6. Новые принципы сети

### Клеточная идентичность

Узел — самостоятельная клетка с постоянным ключом. Интерфейсы и IP меняются, клетка остаётся той же.

### Контрактные связи

Ребро графа — не просто соединение, а подписанный набор возможностей, сроков и ограничений.

### Живые маршруты

Будущая маршрутизация оценивает путь по задержке, потерям, цене канала, заряду устройства и уровню доверия. Маршрут может перестраиваться без центрального контроллера.

### Разделение доверия и транспорта

Обнаружение сообщает только способ связаться. Доверие появляется лишь после проверки ключа и явного действия пользователя.

### Мягкая деградация

При потере прямого пути узел должен переключаться: direct → hole punch → relay → store-and-forward, не меняя идентичность и разрешения.

## 7. Ограничения MVP

- нет виртуального сетевого адаптера;
- нет UDP-туннелей;
- нет NAT traversal;
- нет multi-hop маршрутизации;
- локальное обнаружение не проходит маршрутизаторы;
- интерфейс доступен только на localhost, но CSRF-токен ещё не добавлен.

До реализации этих пунктов проект нельзя считать заменой WireGuard/Tailscale/ZeroTier в боевой инфраструктуре.
