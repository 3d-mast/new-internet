# Архитектура Lichen

## Компоненты

```text
GUI / Local API
      │
      ├── Trust & permission store
      ├── Event log / diagnostics
      ├── Encrypted profile backup
      │
      ├── SOCKS5 ─┐
      ├── HTTP  ──┼── Stream router ── direct TLS
      └── Tunnels ┘                 └─ relay + nested TLS
                                              └─ reverse backhaul
```

## Сетевое ядро

`Node` отвечает за:

- TLS listener;
- проверку Ed25519-личности;
- приглашения;
- прямое открытие потоков;
- выбор relay;
- хранение ожидающих backhaul;
- автоматическое поддержание исходящих backhaul;
- health probes.

## Хранилище

Конфигурация хранится локально в JSON с правами `0600`. Запись выполняется через временный файл и rename. Идентичность хранится отдельно, чтобы настройки можно было менять без регенерации ключа.

## GUI

GUI встроен через `embed.FS`, поэтому Windows-сборка остаётся одним бинарником. Electron, Node.js runtime и внешний web server не требуются.

## Маршрутизация

Порядок открытия потока:

1. Все известные прямые endpoints destination.
2. Если включён `auto_relay`, доверенные узлы с `capabilities.relay`.
3. Relay сначала пытается прямой TCP до destination.
4. При неудаче использует зарегистрированный destination backhaul.

Health-проверки обновляют онлайн-статус, задержку, endpoint и фактический маршрут.

## Модель угроз

Защищаемся от:

- подмены узла по IP;
- подмены сертификата;
- изменения приглашения;
- повторного использования приглашения;
- неявной выдачи прав;
- чтения содержимого промежуточным relay;
- cross-site управления локальным API.

Пока не скрываем:

- факт соединения;
- IP relay;
- идентификаторы origin/destination на relay;
- объём и время передачи.
