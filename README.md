# Mycelium One — new-internet

Экспериментальная самоорганизующаяся сеть поверх обычного IP. Каждый клиент является узлом, может предоставлять TCP-доступ к своей локальной сети, работать выходной точкой в интернет и в следующих версиях — ретранслятором для других узлов.

> Статус: **MVP / research software**. Уже работают защищённые соединения, одноразовые приглашения, локальное обнаружение, точечные разрешения, выход через SOCKS5 и TCP-туннели. Системный TUN-адаптер, NAT traversal и настоящий multi-hop mesh ещё не реализованы.

## Что нового в MYCELIUM/1

- **Личность вместо IP.** Узел определяется постоянным ключом Ed25519. Адрес можно менять, личность остаётся.
- **Разрешения-возможности.** Членство в сети ничего автоматически не разрешает. Для каждого узла отдельно выдаются `use_exit`, `access_lan`, `relay`.
- **Одноразовый контракт подключения.** Приглашение подписано, ограничено по времени и сразу содержит точный набор разрешений.
- **Транспорт независим от роли.** Один и тот же узел может быть клиентом, локальным шлюзом, выходной точкой или позднее ретранслятором.
- **Локальное управление.** Ключи и конфигурация хранятся на устройстве. Центральный аккаунт не нужен.

## Быстрый запуск

```bash
go run ./cmd/mycelium
```

Откроется локальный интерфейс `http://127.0.0.1:47832`.

### Windows

```powershell
./scripts/build-windows.ps1
./dist/mycelium-one.exe
```

### Подключение двух узлов

1. На первом узле нажать **«Создать приглашение»** и отметить разрешения.
2. Передать строку `myc1.…` второму пользователю.
3. На втором узле нажать **«Подключить узел»** и вставить приглашение.
4. Для выхода в интернет выбрать доверенный узел и включить SOCKS5. Приложения направлять на `127.0.0.1:1088`.

## Безопасность

- TLS 1.3 с взаимными самоподписанными сертификатами.
- Ed25519 для идентичности и подписей приглашений/рукопожатий.
- Проверка публичного ключа поверх TLS, а не доверие публичным центрам сертификации.
- Защита от повторного рукопожатия временным окном.
- Одноразовые приглашения с истечением срока.
- Запрет доступа выходного узла к приватным адресам без отдельного `access_lan`.

Полная модель угроз описана в [`docs/PROTOCOL.md`](docs/PROTOCOL.md).

## Порты

| Порт | Назначение |
|---|---|
| TCP 47831 | защищённый транспорт MYCELIUM/1 |
| UDP 47830 multicast | обнаружение узлов в локальной сети |
| TCP 47832 localhost | интерфейс и локальный API |
| TCP 1088 localhost | SOCKS5 при включении |

## План развития

1. Wintun/TUN и полноценная виртуальная IPv6-сеть.
2. UDP hole punching + необязательные rendezvous-узлы.
3. Подписанный gossip-граф и multi-hop relay.
4. Multipath: Wi‑Fi, Ethernet, мобильная сеть одновременно.
5. Android-клиент с тем же протоколом и общим ядром.
6. Обновления, журнал безопасности, импорт/экспорт профиля.
