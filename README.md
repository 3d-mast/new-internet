# Rhizome 3 — сеть сама находит путь

**Rhizome** — следующая природная версия проекта `new-internet`. Корневище не имеет одного центра: оно растёт в нескольких направлениях, обходит повреждения и сохраняет живые участки. Так же работает автопилот Rhizome: проверяет прямые пути, relay и обратные NAT-каналы, после чего выбирает лучший рабочий маршрут без ручной настройки.

> Статус: **рабочий технический preview**. TCP, SOCKS5, HTTP CONNECT, прямые соединения, end-to-end encrypted relay, обратный backhaul через NAT, автопилот и Windows GUI уже работают. Полноценный TUN/UDP dataplane пока не реализован.

## Главное изменение Rhizome 3

После однократного обмена подписанным приглашением обычному пользователю больше не требуется:

- выбирать IP или endpoint;
- вручную выбирать выходной узел;
- включать SOCKS5 или HTTP CONNECT;
- настраивать системный прокси Windows;
- решать, когда использовать direct, relay или backhaul;
- вручную отключать мёртвый прокси после обрыва связи.

Автопилот делает это сам:

1. проверяет все доверенные выходные узлы;
2. оценивает задержку и тип маршрута;
3. предпочитает прямой путь;
4. использует relay/backhaul как резерв;
5. удерживает стабильный маршрут с hysteresis;
6. переключается на лучший рабочий выход;
7. включает системный прокси Windows только после успешной проверки;
8. безопасно снимает системный прокси, если выходы исчезли.

## Совместимость без регрессии

Название приложения и бинарника изменено на **Rhizome**, но wire-протокол намеренно оставлен `LICHEN/2`, а приглашения — `lch1.…`. Это позволяет Rhizome подключаться к ранее установленным Lichen-узлам вместо бессмысленной поломки сети ради новой надписи.

Старая Ed25519-идентичность, доверенные узлы, права и туннели подхватываются автоматически. Если каталог `Rhizome` ещё не создан, приложение использует существующий профиль `Lichen`.

## Windows

```powershell
./scripts/build-windows.ps1
./dist/rhizome.exe
```

После запуска открывается локальная панель. Автопилот включён по умолчанию. Пока проверенного выхода нет, Rhizome **не трогает системный прокси и не ломает обычный интернет**.

## Сервер в любой точке

Один и тот же бинарник работает как публичный relay/exit-node:

```bash
./rhizome --server --no-browser
```

На VPS с публичным адресом интерфейс сети определяется автоматически. При запуске сервер печатает одноразовое приглашение с правами выхода в интернет и relay.

### Docker Compose

```bash
docker compose up -d --build
docker compose logs -f rhizome
```

Открываются:

| Порт | Назначение |
|---|---|
| TCP 47831 | защищённый транспорт LICHEN/2 |
| UDP 47830 | локальное обнаружение |
| TCP 47832 localhost | GUI и API |
| TCP 1088 localhost | SOCKS5 |
| TCP 1089 localhost | HTTP CONNECT |

Для сервера с NAT, firewall или облачным security group входящий TCP `47831` должен быть реально доступен. Программа не может отменить правила провайдера силой мысли — пока что физика всё ещё включена.

## Безопасность

- постоянная Ed25519-идентичность вместо аккаунта;
- TLS 1.3 с точным pinning ключа;
- подписанные одноразовые приглашения;
- отдельные `permissions` и `capabilities`;
- вложенная TLS-сессия через relay;
- relay видит метаданные маршрута, но не содержимое потока;
- локальный API блокирует cross-site запросы;
- резервная копия профиля шифруется AES-256-GCM;
- предоставление своего интернета другим узлам по умолчанию выключено.

## Что пока невозможно гарантировать

Фраза «всегда работает безупречно из любой сети» технически невозможна без публичной инфраструктуры и резервов. Симметричный NAT, корпоративный firewall или блокировка всего исходящего трафика могут запретить прямое соединение.

Rhizome снижает вероятность отказа через direct → relay → backhaul, но для глобальной работы нужен хотя бы один реально размещённый публичный relay/rendezvous. Серверный режим уже запускается одной командой; следующая задача — развёртывание нескольких независимых публичных узлов и UDP/QUIC hole punching.
