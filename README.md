# Reef 4 — самоорганизующаяся сеть с понятным запуском

**Reef** — четвёртая природная версия проекта `new-internet`. Риф состоит из множества самостоятельных элементов, но работает как единая устойчивая система. Reef применяет тот же принцип к доверенным сетевым узлам: прямой путь, relay и обратные NAT-каналы проверяются автоматически.

> Статус: технический preview. TCP, SOCKS5, HTTP CONNECT, защищённый relay и автопилот работают. Полноценный TUN/Wintun dataplane и UDP ещё не реализованы.

## Что исправлено относительно Rhizome 3

Rhizome 3 собирался как Windows GUI-процесс без консоли. При ошибке запуска или неудачном открытии браузера пользователь не видел ничего. Reef 4 устраняет этот класс ошибок:

- `reef.exe` проверяет доступность локального интерфейса перед открытием браузера;
- при фатальной ошибке Windows показывает обычное диалоговое окно;
- журнал всегда записывается в `reef.log`;
- `reef-console.exe` оставлен для диагностики;
- повторный запуск открывает уже работающий интерфейс вместо молчаливого падения на занятых портах;
- `open-reef.cmd` запускает приложение при необходимости и открывает панель;
- CI реально запускает бинарник и проверяет `/api/status` и HTML главного экрана на Linux и Windows.

## Запуск Windows

1. Распакуйте релизный ZIP полностью.
2. Запустите `reef.exe`.
3. Интерфейс откроется по адресу `http://127.0.0.1:47832/`.
4. Если браузер не открылся, запустите `open-reef.cmd`.
5. Для подробной диагностики используйте `reef-console.exe`.

Данные хранятся в `%APPDATA%\Reef`. Если ранее использовались Rhizome, Lichen или Mycelium One, Reef сохраняет существующую Ed25519-идентичность и доверенные узлы, используя прежний каталог.

## Адрес узла

Reef 4 показывает два постоянных логических адреса, вычисленных из Ed25519-идентичности:

- IPv4 из диапазона `100.64.0.0/10`;
- IPv6 ULA из диапазона `fd00::/8`.

Это **идентификаторы overlay-сети**, а не ложное утверждение о созданном сетевом интерфейсе. Пока Wintun/TUN не подключён, Windows не получает отдельную виртуальную сетевую карту и эти адреса не появляются в `ipconfig`. Интерфейс честно показывает `TUN не назначен`.

## Работа одной кнопкой

После однократного обмена подписанным приглашением автопилот:

- проверяет прямые endpoints;
- измеряет доступность и задержку;
- предпочитает прямой маршрут;
- использует доверенный relay или обратный backhaul как резерв;
- автоматически выбирает выходной узел;
- отключает системный прокси при потере всех рабочих выходов;
- переключается на следующий доступный путь без ручного выбора IP.

## Сервер

На чистом Linux/VPS:

```bash
docker compose up -d --build
docker compose logs -f reef
```

Или напрямую:

```bash
./reef --server --no-browser
```

Для глобальной работы за сложным NAT хотя бы один реально доступный публичный relay всё равно необходим. Программа не может обойти провайдера, который блокирует весь транспорт.

## Совместимость

Wire-протокол остаётся `LICHEN/2`, чтобы Reef 4 не ломал доверие и соединения с Lichen и Rhizome. Название продукта меняется, криптографическая идентичность — нет.
