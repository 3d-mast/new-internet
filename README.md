# Lichen — живая защищённая сеть

**Lichen** превращает компьютеры в самоорганизующуюся сеть поверх обычного интернета и локальных сетей. Каждый клиент является полноценным узлом: может подключаться напрямую, предоставлять выход в интернет, открывать локальные TCP-сервисы и передавать сквозной зашифрованный трафик для других узлов.

Название взято из природы: лишайник — устойчивый симбиоз самостоятельных организмов без единого центра управления.

> Статус: **рабочий технический preview**. TCP, SOCKS5, HTTP CONNECT, прямые соединения, обратный relay через NAT, одноразовые приглашения и управление правами уже работают. Полноценный IP/TUN dataplane и UDP пока находятся в разработке.

## Что уже работает

- постоянная Ed25519-идентичность вместо аккаунта и привязки к IP;
- TLS 1.3 с точным pinning публичного ключа;
- подписанное обнаружение узлов в локальной сети;
- одноразовые приглашения `lch1.…` с TTL;
- раздельные права:
  - `use_exit` — использование выхода в интернет;
  - `access_lan` — доступ к указанным TCP-сервисам;
  - `relay` — передача сквозного зашифрованного потока;
- отдельное хранение:
  - прав, которые **вы выдали** удалённому узлу;
  - возможностей, которые **удалённый узел выдал вам**;
- прямое соединение с автоматическим переходом на relay;
- обратные backhaul-соединения: узел за NAT сам регистрирует исходящий канал на доступном relay;
- вложенный TLS через relay — посредник видит метаданные маршрута, но не содержимое потока;
- локальные SOCKS5 и HTTP CONNECT прокси;
- включение системного прокси Windows одной кнопкой;
- TCP-туннели к SSH, NAS, веб-панелям и другим сервисам;
- проверка доступности, задержки и фактического маршрута каждого узла;
- автоматическое переподключение backhaul;
- зашифрованный экспорт/импорт профиля AES-256-GCM;
- локальный журнал событий и самодиагностика;
- современный адаптивный GUI без Electron.

## Быстрый запуск

```bash
go run ./cmd/lichen
```

Панель откроется на `http://127.0.0.1:47832`.

### Windows

```powershell
./scripts/build-windows.ps1
./dist/lichen.exe
```

## Подключение в один клик

1. Первый пользователь открывает **«Пригласить»** и выбирает точные разрешения.
2. Передаёт строку `lch1.…` второму пользователю.
3. Второй пользователь нажимает **«Подключить узел»** и вставляет строку.
4. Для выхода в интернет выбирает узел и нажимает **«Включить сеть»**.
5. Lichen проверяет прямой путь. Если он недоступен, используется доверенный relay/backhaul.

## Порты

| Порт | Назначение |
|---|---|
| TCP 47831 | транспорт LICHEN/2 |
| UDP 47830 multicast | локальное обнаружение |
| TCP 47832 localhost | GUI и локальный API |
| TCP 1088 localhost | SOCKS5 |
| TCP 1089 localhost | HTTP CONNECT |

## Безопасность

- Центрального аккаунта, облачной базы ключей и обязательного управляющего сервера нет.
- Узел доверяется только после проверки подписанного приглашения.
- Членство в сети не выдаёт доступ автоматически.
- Relay передаёт внутреннюю TLS-сессию как непрозрачный поток.
- Локальный API блокирует cross-site запросы и принимает изменяющие запросы только в JSON.
- Резервная копия профиля шифруется AES-256-GCM; ключ получается через PBKDF2-HMAC-SHA256 с 200 000 итераций.

Подробнее: [`docs/PROTOCOL.md`](docs/PROTOCOL.md) и [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Ограничения текущей версии

- Системный режим использует прокси Windows, поэтому не перехватывает приложения, игнорирующие системный прокси.
- UDP, игры и произвольные IP-пакеты пока не проходят через Lichen.
- Wintun/TUN-драйвер ещё не подключён.
- Relay скрывает содержимое, но видит идентификаторы участвующих узлов и время соединения.
- Для первого контакта нужен доступный endpoint приглашавшего узла. После установления доверия NATed-узлы могут держать обратный backhaul через доступный relay.

3. Мультиплексирование нескольких потоков внутри одного транспорта.
4. Несколько одновременных маршрутов и быстрое переключение без разрыва.
5. Android-клиент с общим протоколом.
6. Подписанный gossip-граф для более длинных multi-hop маршрутов.
